## Workflow

- Work on feature branches; open a PR against `develop` for review. Never push directly to `develop` or `main`.
- **Always target `develop`; never stack a PR on another feature branch.** A stacked PR merges into its parent branch, so if the parent merges first the work silently lands off the mainline and GitHub still reports "merged" (this happened to Phase 4). If work depends on an unmerged branch, branch from it but still open the PR against `develop`, and after any merge verify with `git merge-base --is-ancestor <commit> origin/develop`.
- After a PR is merged, confirm the code actually reached `develop` before starting the next phase — commits pushed to a branch _after_ its PR merged are orphaned and need a fresh PR.
- Run git commands against this repo explicitly (`git -C /path/to/wyrmscript`) — the shell's working directory occasionally resets to the parent folder.
- Before pushing: `npm run test && npm run typecheck && npm run lint`.

### Cutting a release

1. Bump `package.json` on a `release/vX.Y.Z` branch and open a PR against `develop` (precedent: #54, #61). The About box reads the version from `package.json` at build time, so there is nothing else to update.
2. After it merges, tag `develop` with an **annotated** tag — `git tag -a vX.Y.Z -m "..."`.
3. `git push origin vX.Y.Z`. The tag push is what triggers the build.

**The tag annotation is the release text**: its first line becomes the release title, the rest becomes the notes. `create_release` reads it **through the GitHub API**, not with `git tag -l --format='%(contents)'` — v0.4.0 shipped with the git version and it silently produced the wrong release, titled `Merge pull request #74 …`, because `actions/checkout` leaves a _lightweight_ tag in the workspace shadowing the real object and `%(contents)` falls through to the commit message. Do not "simplify" it back to a git command. Write it the way it should read on the releases page — the house style is `vX.Y.Z — Headline feature`, matching v0.2.0 and v0.3.0. A lightweight tag has no message and falls back to GitHub's generated commit list, which is not what anyone wants to read.

`create_release` makes the release once before the three builders start, and is idempotent — it will not clobber notes edited by hand afterwards. Do not collapse it back into the build matrix: three parallel builders each creating the release is a race that kills two of them on `422 already_exists`, and on v0.3.0 that shipped a release with no `latest-mac.yml`, silently breaking macOS auto-update while every installer looked fine.

**Do not gate a release on `gh run watch --exit-status`** — it exited 0 on the v0.3.0 run even though the macOS job had failed. Check `gh run view <id>` and confirm the asset list matches the previous release's, name for name.

## Architecture

- `src/main/wyrm/` — project format, isomorphic-git operations, IPC handlers, settings. Pure Node; keep it Electron-free where practical so it stays unit-testable (`project.ts` and `git.ts` are imported directly by tests).
- `src/preload/index.ts` — the only bridge; mirrors the `WyrmApi` interface in `src/shared/types.ts`.
- `src/renderer/src/` — React UI. `lib/api.ts` falls back to a full in-memory mock when `window.wyrm` is absent, so the browser preview exercises the whole UI without touching disk.
- A project is a folder (`Name.wyrm/`) that is also a git repo: `project.json` (binder tree + trash), `documents/<id>.md` (YAML frontmatter + Markdown body), `glossary/` + `characters/` + `world/` (one frontmattered file per story-bible entry), `.git/`.

### Implementation landmarks

Worth reading before touching the neighbouring code:

- `lib/markdown.ts` — the only bridge between stored Markdown and TipTap JSON. Supports paragraphs plus `**bold**`, `*italic*`, `==highlight==`, hard breaks. Serialization groups maximal runs per mark so round-trips are a fixed point; there are tests asserting that, including a fixture copied verbatim from a real project file.
- `main/wyrm/git.ts` — `commitAll` compares **blob hashes against HEAD** rather than trusting `statusMatrix`'s stat-based dirt check. Do not "simplify" that back: same-length edits landing inside one mtime second are invisible to stat comparison (racy git), which for this app means a silently lost draft.
- `main/wyrm/entities.ts` — story-bible entries on disk. Unlike `DocMeta`, which `project.ts` passes through whole, entity frontmatter is **read field by field and written only when set**: a new `Entity` field needs a line in `EntityFrontmatter`, `parseEntityFile` _and_ `writeEntity`, or it is silently dropped on read and never written. Numeric fields are written on `!= null` (0 is a real board coordinate); clearing one means deleting the key, never assigning `undefined`. **Portraits** (F-47) live beside the entry as `<dir>/<id>.<ext>`, referenced by the project-relative `portrait` field; main derives every path from the entry's type and id and rejects an id with a separator or `..` (`main/wyrm/plainId.ts`, the one check shared by every one-file-per-id store — map pins, map shapes, map marks and board strings refuse such an id on write and delete, and skip a file carrying one on read), the renderer only ever names an id, and the image crosses the bridge as a data: URL (the shipped CSP already allows it; `file://` is refused in dev by Chromium, not CSP). `deleteEntity` removes the portrait with the entry.
- `lib/entities.ts` — the auto-link matcher: longest-match-wins alternation, Unicode lookaround word boundaries (accents work, possessives link), regex-escaped terms, collisions recorded rather than shadowed.
- `lib/entityLinks.ts` — the ProseMirror plugin that draws links as decorations. Scans per text block (so names split across marks are still found) and is debounced; `refreshEntityLinks(editor)` forces a re-scan after the index changes.
- `lib/compile.ts` — compile/export. Binder + documents are flattened into a format-independent block list (`CompileBlock` in `shared/types.ts`) first, and every output format is a pure function of that list, so selection/order/separator rules exist once. Markdown output goes back through `docToMarkdown`, which is what makes compiled Markdown byte-identical to the stored files. `lib/docx.ts` is a dependency-free OOXML + ZIP writer; keep it that way.
- `main/wyrm/sync.ts` — the GitHub sync engine. **The working tree is the single source of truth for every sync commit**: isomorphic-git's `merge` never touches the working directory, so it is only ever used as a conflict detector and a content oracle (`noUpdateBranch` both times), and the merged state is materialized to disk before being committed with explicit parents. Prose never auto-merges — frontmatter merges structurally, but both-device edits to a document's text always go to the writer. The header comment explains which silent-data-loss bug each rule prevents; do not "simplify" any of them away. Transport is injected (`SyncTransport`), which is how the whole engine is tested against real repos with no network. **A merged frontmatter never carries an undefined value**: the per-key merge runs over the union of both sides' keys, and a key one device _cleared_ (the writers omit unset optional keys) merges to `undefined`, which gray-matter throws on — the sync failed outright instead of merging. Keys whose merged value is undefined are deleted after every rule has run; Tidy clears `boardX`/`boardY` constantly, so this is routine, not rare. Two tests in `sync-engine.test.ts` fail with the exact YAML exception if the sweep is removed. **Content the engine did not compose travels as bytes** (`blobAt`; the merge target is `string | Uint8Array`; `materialize` writes each as-is): the merge used to round-trip every file through `TextDecoder` and write it back as UTF-8, which turned a PNG neither device had touched into U+FFFD soup on the first divergent merge while reporting `merged`. Three tests push invalid UTF-8 through a merge in each direction and assert `Buffer.equals`; do not reintroduce a text path for anything but the frontmatter merges the engine itself writes. **The merge driver is isomorphic-git's default reproduced** (`mergeText`: its unexported `mergeFile` over the same `diff3`, pinned as a direct dependency to the version it pins), used for the detector and the oracle alike: a both-changed file that merges cleanly keeps that merge even when another file conflicts (I-13 — the oracle's driver used to return _ours_ for everything), and a file that is not text is never line-merged but goes to the writer as bytes (I-17). "Not text" is judged on the **bytes** (`isBinary`: invalid UTF-8 or a NUL), never on a decoded string — a U+FFFD the writer typed is text. isomorphic-git gives the driver only a file's _name_ and decoded text, so the non-text both-changed files are found before merging (`binaryMerges`, keyed by name and both sides' text). Every one-file-per-record collection merges field by field (`isFrontmattered`); the corkboard's and map's records (`isRecord`: strings, relationships, plotlines, map pins, shapes, marks) are **strict** — the same field changed differently on both devices is a conflict, because their labels, names and geometry live in frontmatter — while documents and entries keep "this device wins" for a field (their prose is protected separately). Positions merge as a pair (`PAIRS`: x/y, boardX/boardY), so two moves never combine into a point neither device chose. Add a new collection's folder to `RECORDS`. The no-oracle fallback throws rather than keep one side if a file it expected to merge cleanly does not.
- **Signing in to GitHub is app-level** (`GitHubSignIn`, `getGithubAccount`/`setGithubClientId`), not a project's: Sync and Bring Down from GitHub both use the one panel, because a new computer has no project open and still needs to sign in to bring one down (I-18). The app carries its own OAuth client id (`BUILT_IN_CLIENT_ID` in `github-auth.ts`, read through `clientIdOf`; a saved one wins), so the client-id step only shows if that is ever removed. The panel calls the API itself and refreshes nobody's status — the caller does that in `onSignedIn`, or the panel is swapped away before it can say the sign-in worked.
- `main/wyrm/clone.ts` — the other direction of sync (F-43): making a local project out of one that already exists on GitHub. Hand-rolled init-remote-fetch-checkout rather than a `clone` call, with the fetch going through the **injected `SyncTransport`** — the same seam `sync.ts` uses, which is why this is tested against real repositories with a bare repo standing in for GitHub. Two rules: a destination with anything already in it is refused (as `restoreBackup` refuses one), and **anything failing after the folder is created removes the folder** — "not a WyrmStar project" is the expected case here, and a half-made project left behind makes the next attempt fail on "already exists" for a folder the writer never made. The clone is written as `mode: 'github'` with its remote set, so it syncs immediately; the test that proves it is a real peer is the one that syncs straight after cloning and gets `up-to-date`.
- `main/wyrm/backup.ts` — mirrors a project into **one or more** second repos on disk (F-01, extended to several targets by F-40). **isomorphic-git has no local transport** (`push` demands an HTTP client; `file://` and bare paths both fail), so this copies objects then moves refs, the way git's dumb protocol does. Three invariants hold it together and none are optional: objects land before refs move, every object is staged and renamed into place, and updates are fast-forward only with nothing ever deleted. The comment block at the top explains why each one prevents a specific, silent corruption; they are per-target and unchanged by multi-target. What multi-target adds: targets are independent, so every one is attempted and every result reported rather than the run stopping at the first problem; an **unreachable target is a skip, not a failure** (an unplugged card is the normal state of removable media, and flagging it would train the writer to ignore the signal); and each target keeps its own `lastBackupAt`, because falling out of date separately is the whole point. Runs are sequential — `backupProject` commits the working tree first, so concurrent runs would race `commitAll` against one repo. Backup settings migrate from the old single-`path` shape **on read**, keeping the path and its timestamp; never "simplify" that away, since losing it leaves a project with no second copy while the UI still claims one.
- `lib/windowGeometry.ts` — the arithmetic behind dragging and resizing a project window (F-41 step 4). Pure and DOM-free on purpose: this is where a sign error strands a window the writer cannot reach (above the top edge there is no title bar to grab; too small and the close box stops existing), and jsdom has no layout engine, so only pure functions can be tested honestly. Pointer handlers feed deltas in and do no measuring of their own. Two rules that look wrong but are not: resizing **never shrinks** a window to satisfy the desktop edge, because a window dragged mostly off the right legitimately overhangs it; and a desktop measurement narrower than `MIN_WIDTH` is **rejected**, because an empty `.desktop` measures exactly its own 28px of padding and a window sized from that is unusable.
- `App.tsx`'s **project windows** (F-41) — one `.mac-window` per entry in `openPaths`, cascaded, with the focused project rendering the live app and the rest rendering from their parked slice as a caret-less snapshot (`InactiveProjectWindow`). A background window cannot host a real editor because only the focused project has live state. Per-window close boxes close **their own** project and stop their own mouse events, so they never focus-then-close; getting that wrong throws away the wrong novel's window with no warning. Window stacking must stay below `.menu-drop` (90) and nowhere near `.dialog-overlay` (300) — see the z-index budget comment in `retro.css`. `openPaths` is **stacking** order, so focusing moves a path to the end; positions are explicit, so that raises a window without moving it. Two pointer rules that are easy to undo by accident: focus is on **`pointerdown`, not `mousedown`**, because the drag handler's `preventDefault` suppresses the compatibility mouse events entirely; and the grow box **stops propagation** so a corner grab resizes in place, since raising swaps the focused slice and unmounts the component mid-gesture. The three title-bar boxes share one sizing rule; a control styled on its own drifts out of it (I-12). `.title` has `margin: 0 auto`, so the right-hand free space belongs to whichever control carries `margin-left: auto` — that has to be the **first** control on the right (minimise), with zoom given a fixed gap after it, or minimise lands mid-bar.
- `store.ts`'s **project slice** (F-41) — the focused project's state lives in the flat store fields; every _other_ open project is parked under its path in `parked`, with `openPaths` holding window order. There is exactly one home for each project's data and nothing is mirrored, so no two copies can drift, and every action keeps acting on "the" (focused) project. `SLICE_KEYS` is the single declaration of what belongs to a project — `ProjectSlice` is `Pick`ed from it, so adding a per-project field means adding it there and nowhere else. **`editor` is in the slice but is always parked as `null`**: the TipTap instance belongs to the component that mounted it and is destroyed on unmount, so restoring the handle hands back a corpse. A parked project still checkpoints, backs up and syncs, via `commitParked`/`syncParked` — `commitNow` acts on the focused project, so routing a background project there would mean it silently never writes history or leaves the machine. **A background sync that pulls or merges marks the slice `stale`**, and `focusProject` re-reads from disk before the writer can touch it: sync is bidirectional, so the files can change while the slice still holds the binder and open document from before, and typing into that would write stale text over work that just arrived from another device. Never drop that flag or the reload.
- **Minimising** (F-41 step 6) — a minimised project is _still open_: parked state, background work running, just not drawn. Never make `minimizeProject` dispose the runtime or call `api.closeProject`, or tidying the desktop silently stops a novel checkpointing and changes what reopens next launch. The icon strip is **layout, not an overlay** — `.desktop` is a column of `.desktop-windows` (what `useDesktopSize` measures) plus the strip — because a floating strip covers the status bar of any window reaching the bottom, and a lone `.main-window` ignores the measurement entirely since it positions by CSS inset.
- `store.ts`'s **`ProjectRuntime` registry** (F-41) — the debounced save, the Autosave interval and the dirty flag, keyed by project path. They were module-level singletons, which is silent data loss once a second project can be open: one project's keystroke cancelling another's pending save, one project's open stopping another's checkpointing, one commit clearing another's dirty flag. Never reintroduce a shared timer or flag here, and call `disposeRuntime` on every path that closes a project. Note the routing guard in the auto-commit callback — it is the seam where per-project state will pass a path to `commitNow`.
- `lib/corkboard.ts` and `components/Corkboard.tsx` — the story's pieces as index cards, **placed, not flowed**: scenes (every scene-tagged document, binder order), and characters and locations put on the board deliberately (`entity.onBoard`, the World Map's model — F-45). A card stays where the writer drops it; the position lives on the scene (`boardX`/`boardY` in `DocMeta`) or the entry (same fields on `Entity`), so it survives the view, the project and a sync. A card nobody has moved has no stored position and falls back to its slot in binder order, so a project that has never used the board is unchanged and nothing is written until a card is actually moved or the board's order applied. **Tidy** clears every stored position (scenes and entities, keeping `onBoard`) and is the only way back from an arrangement. It **must re-read the documents** after writing: the board reads them once when it opens and clearing a position does not change `project`, so without the reload it falls back to stale copies and every already-placed card springs back. Placement escapes this only because it holds the new position in the component until the write lands; entity cards come from the store's `entities` and need no reload. Its grid is as square as the cards allow (`tidyColumns`), not as wide as the board. **Stack** is a view toggle, never written anywhere (`stackLayout` is pure); a card dragged out of a pile is placed and stays out until Unstack. Dragging deliberately does _not_ reorder the manuscript — the binder is still how the book is ordered; **Apply Order** (`boardOrder` → `applyBoardOrder`) is the deliberate write-back: rows by clustering from the row's _first_ card (`ROW_TOLERANCE`), scenes reordered only **within their own parent** with every fixed node keeping its index, the enabled state asked **per folder** (`boardOrderDiffers` groups by `parentId`, since a cross-folder arrangement is one applying cannot change), **never while stacked** (the piles' cascade is not the writer's arrangement), and every unplaced scene **pinned at its slot** on apply — the one time positions are written for cards nobody dragged — so the board keeps reading in the order just applied. **Undo Apply is a per-folder order record, never a snapshot** (`BoardUndo` in `boardUndo`, in `SLICE_KEYS`; `applyBoardOrder` returns it and records it before the write; `undoBoardOrder` re-applies each folder's entry kept to the scenes still there): a binder snapshot put back wholesale dropped a scene added in between from binder _and_ trash, orphaning its file; a whole-board order reverted folders Apply never touched and re-ranked a scene moved elsewhere. `loadProject` clears it — a different project is a different undo, and a clone shares the original's ids. Nothing else in the app restores binder order. **The board is keyboard-driven too**: arrows go to `nearestCard`, ⌥+arrows nudge through `placeCard` (the one placement path, shared with drag — a nudge out of a pile pulls the card out), ⇧Return turns a scene card over, and with the string tool up a click with `detail === 0` (keyboard) pins at the card's top centre; tests that simulate a mouse click must pass `detail: 1`. Pins are focusable buttons only while the tool is up. Add Card's open state is store-level (`addCardFor`, `openAddCard` — ⌥⌘N, the Corkboard menu, the palette), cleared in `focusProject`/`loadProject` and by a store subscription when the view leaves the board (not an unmount cleanup — StrictMode runs those on first mount). ⌥⌘N and the menu refuse while any `.dialog-overlay` is up. Keyboard nudges write after `NUDGE_SETTLE`, flushed on unmount. **Never move focus onto a button while the key that caused it may still be down** (`afterKeysUp`): Chromium delivers that Return/Space to the newly focused button. **A card opened from the board is a detour, not an arrival**: `Corkboard`'s `open` passes `{ kind: 'corkboard', cardId, scrollTop }` as `selectDoc`'s `returnTo` (or `showEntity`'s `from`), so Esc comes back to the board, scrolled where it was, with that card focused; any other `selectDoc` call still clears the history. The restore waits for the board's `measured` flag, not a non-zero width, because the width is legitimately 0 under the test stub, and it is **one-shot** (`settleBoardReturn` clears the place from the view). In Focus Mode on the page, Esc leaves Focus Mode before it goes back. **A control that uses Esc for itself must `stopPropagation()`** so App's window listener never sees it; never gate Esc-as-back on `defaultPrevented`, because ProseMirror prevents the default of every Esc in the editor. **The editor saves on unmount** (I-15) — `flushSave` captures the text before its first await, so it must be called while the store still holds the editor; and the board overlays the open scene's body from `activeDoc`, because its own read can beat that save. **The back of the card** (F-42, `lib/cardBack.ts`, `components/CardBack.tsx`) is the scene's outline — synopsis, act, scene type, location, conflict, cast — reached from the dog-ear on every scene card. `withBack` is the only writer and **deletes a cleared field rather than writing it empty**; `setCardBack` writes nothing when nothing changed, and writes through `updateDocAt`, the one focus-safe metadata writer (looks the open document up in the flat fields or the parked slice, whichever holds it now, and dirties the path it wrote). Enter saves and turns to the next scene; **every way of closing saves — there is no Cancel**, deliberately, including a teardown when another project comes to the front (it flushes to the path the card was turned in); only a failed save offers Close Without Saving. **A save is a patch of what the writer edited** (`backPatch` against the card's starting point, `withPatch` over the file as it is now), never the whole back — the board's copy can be older than disk after a sync. Never `disabled` the back's fields while saving: Chromium drops focus to the body and the Enter-to-turn loop dies. Each `.scene-card` is `isolation: isolate`, so a buried card's corner controls cannot cover the card on top. A cast entry for a deleted character is kept and hidden, never cascaded. **The pins are written by `applyBoardOrder` itself** (its `pins` argument), never by a second store call after the save: a save is an await a writer can focus another window across, and anything that reads `project`, `activeDoc` or `markDirty()` afresh after it acts on the wrong novel — with a clone's shared ids, writing the other novel's open text into this one's file. `writePositions` looks the open document up in the flat fields or the parked slice, whichever holds it _now_; `persistProject` dirties the path it saved; `undoBoardOrder` clears its record the same way, in a `finally` (a failed save left a redo on the button). `layoutCards` **deals an unplaced card past any slot more than half covered by a placed card** and shifts the dealt cards after it: after Apply every card is pinned at the old column count's slots, and a scene added at a square-number count was otherwise dealt onto one. Cards drag on **pointer events, not HTML5 drag-and-drop**, unlike the binder: the board shipped on `draggable`/`dataTransfer` and cards would not drop, and the bug survived two fixes because **nothing available here can drive native drag-and-drop** (jsdom has no `DragEvent`; the preview's remote-debugging mouse does not start one), so every check short of launching Electron reported success. Three rules the pointer version depends on: the gesture is **tracked on the document from the press**, not on the card — a first move that lands off the card (a fast flick, or the preview's coarse drag tool) is otherwise never heard and the card never moves; **no capture is taken**, because capturing on the press redirected the whole gesture to the wrapper and the card's own button never saw its click; the click-suppression flag is **cleared on every press**, since a drag ending over a different card fires its click on the board and nothing consumes it. The help ids on cards are written out as two literal `data-help` strings, not computed — `tests/guided-help.test.tsx` reads source for literals. Cork is a `--cork` palette variable beside the dithers, and **every palette must restate it with its own ink**; `tests/palette-fonts.test.ts` fails by name if one is missing or wrong. The grain is a 96px tile drawn at its own size with rejection-sampled positions; do not scale it or hand-place flecks. The board **replaces** the manuscript view: the binder is hidden while it is up, and Add Card, the five outlining views, Apply Order (and Undo Apply after one), String, Stack and Tidy are pinned to the board in its place. **Strings** (F-46) are a project collection like map pins (`strings/<id>.md`, `main/wyrm/boardStrings.ts`, `boardStrings` in `SLICE_KEYS`); each end is anchored to a **card by offset**, never to a point on the cork, so a string survives drags, stacks and Tidy, and `stringPoints` is evaluated against the positions of the moment so it follows a card mid-drag. A string whose card has left the board is **hidden, never cascaded**: the card may come back. `--string` is the one colour outside a palette's two inks, declared at `:root` and deliberately absent from `palette-fonts.test.ts`'s ink loop, which would require it to be ink-coloured. A palette **restates it** (with `--string-dash`/`--string-glow`) when the red falls under 3:1 on its paper or its medium has no red — the one-colour CRTs draw it in the phosphor with a glow, Blueprint as a dashed construction line — and `palette-fonts.test.ts` resolves every palette's string through the cascade and holds it to 3:1. **Portraits print as a duotone in the palette's two inks** (`.portrait-print`: the image in greys multiplied onto `--duo-hi`, then `--duo-lo` over it with `lighten`); a light-ink palette must swap `--duo-lo`/`--duo-hi` or its portraits print as negatives, and the same test checks that for all sixteen. Halftone adds a dot screen. The string layer takes no pointer events — pins take clicks only while the tool is up — so cards under strings still drag. **Strings carry labels, and a string between two characters is a `Relationship`** (Character Graph data), not a board string: after the second pin a label field opens at `stringMidpoint`, and only then is anything made. Relationships between characters both on the board are drawn by `relationshipStrings` — derived, never stored as strings — anchored at `facingPins` so they hang between cards rather than through one. The board loads relationships itself. Label tags are HTML over the string layer (`.board-labels`), text with the tool down and buttons with it up; the label field's Esc is its own (the string tool's capture listener skips it). Relationships between the same pair are spread apart (`PARALLEL_SPACING`, `side`) and tags placed by `tagPlace` so they never cover pins; the field ignores a blur while `document.hasFocus()` is false, and a draft that cannot be kept stays open with its reason rather than vanishing.

- `lib/worldMap.ts` and `components/WorldMap.tsx` — the world map (F-12), a **full-window view** (`MainView` `{ kind: 'map' }`, a detour like stats; the binder is hidden as for the board), not a dialog. The extent is `ProjectData.mapBounds`, **an origin plus a size**: growing north or west moves the origin, never the content, so nothing stored on the map is rewritten, and `boundsOf` widens it to take in any pin outside it. Zoom is 0.5/1/2 only (other steps blur the 1-bit art); the canvas is drawn at map size and CSS-scaled inside a sizer of the zoomed size. Opening a place passes the map's scroll/zoom/pin as `showEntity`'s `from`; the restore waits for the pins to load and is one-shot (`settleMapReturn`). Pin moves go through `moveMapPinAt(path, …)` — path captured when the move is made, and a move never creates a pin — because a settled nudge can be written after a focus change. Pins are an unscaled layer at zoomed positions (the art scales; names must not). `afterKeysUp` lives in `lib/keys.ts` for both the board and the map. **Drawn shapes** (`MapShape`: land, area, border) live one per file in `map-shapes/` — never `map/`, which is the pins' folder (`listMapPins` now skips non-pins, but a shared folder is still wrong). `lib/mapShapes.ts` is the geometry; the view's tools are Hand/Land/Area/Border, where a click adds a point and a drag always pans; shape writes go through `updateMapShapeAt(path, …)`. The sea, hatch and graticule are SVG patterns filled with `var(--ink)`, so every palette draws them in its own ink. Keep `.map-hint` one fixed-height line: a hint that wraps moves the map mid-drawing. Shapes are chosen on a **still click, from `onMapDown`** — never on the shape's own press, or a drag that starts on land cannot pan. The drawing keys (Esc/Return/Backspace) live on the **`.world-map` root**, not the scroll area, so they work with focus on a zoom button; Return on a focused button stays the button's. Pins are inert (no pointer events, `tabIndex -1`) while a drawing tool is up. The extent (`boundsOf`) takes shape points as well as pins. Anything that unmounts a focused handle moves focus first (to the shape, or the corner now in its place). Shape kinds, which are closed and their minimum points live in `shared/types.ts` only — never compare kinds by hand. Rivers curve (`smoothPath`, repeats dropped; `midpoints(…, smooth)` puts handles on the curve); **all road casings are drawn in one pass before any road body**, or junctions close, so a road's selected/focused look is a class on its casing (`keyFocus`), not a nested selector. `.map-shape-body:focus` has `outline: none` — Chromium rings clicked SVG shapes in orange otherwise. **Marks** (`MapMark`: nineteen stamps and `label`, each with an optional `size` from `MARK_SIZES`, the usual size never stored) live in `map-marks/<id>.md`; `lib/mapMarks.ts` holds the stamp art, `STAMP_GROUPS` (the palette's order — every stamp kind must be in exactly one group, and a test holds that) and where names go (`labelAnchor`: area centroid for outlines, halfway by length for lines). Mark and shape-name writes are path-addressed (`createMapMarkAt`, `updateMapMarkAt`, `renameMapShapeAt`), resolved against whichever slice holds that path _after_ the write. The name field (`Naming`, opened only through `openNaming`) is kept on Return, on a blur — **unless the window lost focus** (`document.hasFocus()`) — and **on unmount**, to the path it was opened in; a label is made only once it has words. Stamps are chosen from `StampPalette` (one toolbar toggle, not a button each — the bar must stay short); it closes on its own Esc (stopped, since Esc is also "back") and on a press elsewhere. **A place can be drawn as a stamp** (`MapPin.stamp`/`size`, `styleMapPinAt`, which queues with `moveMapPinAt` per pin): its row's Show as… opens the same `StampPalette` with `allowPin`, a size row and `closeOnPick={false}`, rendered at the `.world-map` root because the side panel would clip it. Size: one control beside the hint line acts on the chosen mark, else on the next one made; [ and ] step a chosen mark's size from the mark or the map root. A press on a mark with the Hand moves it; a press on a shape pans. Delete/Backspace on the map root removes whatever is chosen (I-19): a click chooses without always focusing (hit bands take no focus), so never rely on the item's own keydown alone. `reloadAfterRemoteChange` re-reads all three map layers. **Measure and scale**: the Measure tool's route is component state, never stored; `ProjectData.mapScale` (`setMapScale`) says what map pixels are in the story's unit and a day's travel by foot, horse and ship, set in `MapScalePanel` from a measured route or one grid square (100 map px) — never asked of the writer in pixels. `lib/mapScale.ts` is the arithmetic (`describeRoute`, `scaleBar`, `formatDays` to the half day).
- `lib/syncState.ts` — the single answer to "is this project actually connected" and "does a second copy exist anywhere". It exists because the surfaces disagreed: `mode` is stored intent, `remoteUrl` is read live from `.git/config`, and a remote removed outside the app leaves them contradicting each other. Gating on `mode` alone left Sync Now live with nowhere to push and made the status bar report `◆ SYNCED` for a project that was not synced. Anything answering "can we sync / is the work off this machine" uses these predicates rather than testing `mode` by hand.
- `lib/search.ts` — one index behind both ⌘K and ⇧⌘F, so "what is findable" is decided once. **Searches the plain-text projection, never the stored Markdown**: bodies carry `**`/`==` mid-sentence, so raw search silently misses any phrase spanning a mark and shows storage syntax in snippets. Parsed bodies are cached by string.
- **A button the writer might reasonably press is never silently dead.** If pressing it cannot work yet (an empty name, a duplicate), leave it enabled and say why beside the field (`role="alert"`, `aria-invalid`), the way the Plotlines dialog's Add does (I-14). Disable a button only when its state is obvious from what is on screen, and `.btn:disabled` (the dither through the label, dotted border) must keep existing — without it, a disabled button looked exactly like a live one.
- `lib/useFocusTrap.ts` — dialog keyboard containment. Without it Tab walks out of a modal into the manuscript behind it, letting a keyboard-only writer type into a document they cannot see. Filters focusables by attribute, not layout, so it does not depend on a real layout engine.
- The **Corkboard menu** — the board plus the five story-structure views (timeline, plot graph, plotlines, character graph, world map), which were previously split between View and Project. They are the same scenes seen differently, so they live together. Three things state that set and all three must agree: the menu, the board's pinned strip (`Corkboard.tsx`), and the **command palette's subtitles**, which name an item's menu and are _searched rather than displayed_ — a stale one sends a writer to a menu the item is not in. `⌥⌘B` toggles board↔manuscript via `toggleCorkboard`, and like `⌥⌘F`/`⌥⌘T` it must test `e.code`, not `e.key`: Option remaps the character on macOS, so checking `'b'` fails silently on the platform it is for.
- `lib/help.ts` and `components/HelpLayer.tsx` — guided help (F-44): the **?** in the status bar turns on a mode where hovering a control explains it. Copy lives in `HELP_TOPICS`; a control opts in with `data-help="<id>"` and needs no other wiring, since the layer listens on `document` and walks up from the target. `tests/guided-help.test.tsx` reads the renderer source and fails both ways — a marked control with no copy, or copy for a control that no longer exists. Three rules that are easy to undo: clicks on a marked control are **swallowed** (asking what minimise does is not asking to minimise); Esc **stops propagating** (it is also "back" and "close the dialog", so leaving help would otherwise also move the writer); and placement is the pure `tipPosition` (jsdom has no layout engine), which flips the tip above a control with no room below — the binder is most of the window tall and did exactly that.
- `lib/shortcuts.ts` — the one list behind the ⌘/ legend. A shortcut is already stated twice (the menu item advertising it, the handler implementing it); the legend is a third, and one that drifts teaches a key that does nothing. `tests/shortcuts-legend.test.tsx` reads `MenuBar.tsx`'s own source for every `shortcut:` literal and fails if it is missing here, so add new shortcuts in both places. It also carries the keys no menu mentions (⌘Y, ⌘P, ⌥F, Esc), which is half the reason it exists.
- **`.dialog-buttons` wraps.** The row is justified to the right, so one too wide for its dialog overflows _backwards_, out of the left edge, rather than being clipped where it would be noticed — that is how a third Welcome button ended up hanging off the dialog. Button widths depend on the palette's chrome face (sixteen of them), so a fixed dialog width never prevents this on its own; `tests/menu-bar-stacking.test.ts` reads the rule from source.
- `components/MenuBar.tsx` — the WAI-ARIA menubar pattern (roving tabindex, ←/→ with or without a menu open, type-ahead, Esc). Follow the pattern rather than extending ad hoc; it is also what makes the bar screen-reader navigable.
- `App.tsx`'s **`closeAllDialogs`** (F-41 step 5) — a focus change closes every project-scoped dialog. Dialogs are app-modal and read the focused project live, and the menu bar sits _above_ the dialog overlay (310 against 300), so the project underneath an open dialog can change while it is open. Without this, Compile opened for one novel silently retargets and exports another. About is exempt because nothing about it is project-scoped.
- `components/ErrorBoundary.tsx` — wraps the root and each dialog. An error thrown from a React effect otherwise unmounts the whole tree, which once left the app a dead white window with no way back to the manuscript.

## Testing

`npm run test` (vitest). Conventions:

- Pure logic and the main-process modules get plain node tests; `main/wyrm/project.ts`, `git.ts`, and `entities.ts` are Electron-free precisely so they can be imported directly and exercised against real temp dirs (`fs.mkdtemp`), including real git repos.
- UI failure modes and the editor get jsdom tests (`*.test.tsx`, `// @vitest-environment jsdom`), driving a real TipTap editor or React Testing Library rather than asserting on mocks.
- Don't commit tests that depend on a specific machine's files.
- When a bug is found, the fix lands with a test that reproduces it — every `I-nn` in the roadmap has one.

## Delegating work

Splitting a phase across agents works when the contract is written down first: define the types in `src/shared/types.ts`, then hand a subagent an **exclusive file list** (and an explicit do-not-touch list) so two writers never share a file. That is how the story bible's storage/IPC layer was built in parallel with its matching engine. Mechanical, well-specified layers (storage, IPC wiring, mock implementations, CSS themes, export templates) delegate well; subjective design and tightly coupled architecture do not.

## House rules

- **The page is sacred**: no spellcheck, no autocomplete, no AI suggestions, no notifications in the writing terminal. Formatting is bold / italic / highlight only.
- **Nothing is ever lost**: any operation that replaces text (restore, adopt variant, bulk change) must safety-commit first. Never rewrite history — corrections are new commits.
- **The UI never says "git"**: it says checkpoint, version, variant, restore.
- Chrome uses the bitmap font and manuscript prose a serif — **except where a palette says otherwise.** Manuscript (F-15) is the first palette to repaint both faces via `--font-chrome`/`--font-prose`; a palette that does this must keep the prose face a _reading_ face, with atmosphere confined to the chrome. Because `data-palette` lives on `.screen`, any font/colour a palette overrides has to be **re-declared on `.screen`** — `body` sits above the attribute, and inheritance passes the already-resolved value down, so a variable resolved on `body` silently ignores every palette. Themes remap `--ink`/`--paper` and the dither/accent variables from one place in `styles/retro.css` — add new themes there rather than hardcoding colours. A palette is `[data-palette='name']` on the root and **must restate all six SVG data-URIs** (three dithers, two scrollbar arrows, and the corkboard's `--cork` grain) with its own ink baked in; forgetting them leaves the previous theme's patterns behind. Glow and scanlines belong to the CRT palettes only. Most palettes flatten to strict two colours (`--highlight-bg: transparent`, accent-\* vars collapsed to `--ink`); a couple (Ledger, Arcade) deliberately don't. **`.page mark`'s box outline is unconditional, not scoped to any accent/palette combination** — it used to be `[data-accents='1bit']`-only, which left a highlight fully invisible under 4-bit accents plus any palette that suppresses the colour wash. Don't re-scope it; that reintroduces the bug. Page geometry (`--measure` in `ch`, `--prose-size`, `--prose-leading`) is set inline on the root from persisted appearance settings.
- A failure in one panel must never take down the app. Dialogs own their loading/empty/error states.
- **Never return a fresh object from a zustand selector** (`s.entities.filter(...)`, `.map(...)`): the snapshot differs on every read and the component re-renders until React throws "Maximum update depth exceeded". Select the stable slice and derive during render.
- Auto-linking is _derived_ data: story-bible links are ProseMirror decorations, never marks, so they never get written into the manuscript file.

## Verifying UI work

`npm run dev` runs Electron; the same dev server URL opens in a plain browser against the mock. Native dialogs (New/Open Project) and real filesystem/git behaviour exist **only** in Electron — the browser preview is mock-backed and never writes to disk.

- **Drive real clicks.** Synthetic events dispatched straight at elements bypass hit-testing and have hidden real bugs here: a click-away overlay stacked above a menu made every menu item dead, and the original verification missed it entirely because it fired events directly on the elements.
- Editing a file that the running app has hot-reloaded can reset store state mid-test; reload before drawing conclusions from a half-finished interaction.
- After changing main-process or preload code, **restart Electron** — a stale bridge against a fresh renderer produces failures that look like application bugs (this caused the white-screen report).
